Why GitHub views dropped, and what to do about it

GitHub repo views fell from about 20K to 12 to 14K per two weeks. This page explains where that traffic went, tests the likely causes, and lays out options.

Analysis as of Oct 21, 2026 · Sources: GitHub Traffic API (22 repos, daily), Microsoft Clarity (Hub website, daily), Hub change history, enablement session log

1. Summary2. Explanation3. Details4. OptionsWhich repos dropped →

1Summary

We are not losing our audience. We are losing the GitHub count of it.

Hub website traffic grew steadily through October, back to its post-August-workshop level, and the number of distinct people visiting is up. GitHub repo views fell because people now find, preview and download templates through the Hub instead of browsing GitHub, and some of our own link settings stop GitHub from crediting those visits.

About a third of the drop is a real cool-down from the August surge, mainly in search traffic. That part is normal and worth watching, but it is not a collapse.

2Explanation

The two numbers we watch moved in opposite directions from the same week. That is the signature of traffic moving, not traffic disappearing.

Hub website human sessions per weekdayGitHub repo views per day (all 22 repos)Indexed: week of Sep 14 = 100

What changed, in plain terms

1. The Hub became the front door

The Sep 10 Reports redesign and the Sep 25 guide rebuild put setup steps, previews, videos and template downloads on the Hub itself. People no longer need the GitHub page to evaluate or get a report.

2. Links now skip or hide from GitHub

Template buttons download the file directly, which GitHub does not count as a view. 140 links were set to hide their source, so GitHub stops crediting the Hub for visits it sends.

3. Teams shares moved to the Hub

On Sep 30 the Hub got proper link previews for each report. People now paste Hub links into Teams instead of GitHub links. Teams visits to the Hub rose while Teams visits to GitHub fell.

On top of this, there is a genuine fade after the August LevelUp surge. Repos with no Hub changes at all still fell, and search-driven GitHub visits drifted back toward their pre-August level.

4Options

The first two fix the measurement so we see the real picture. The rest address the genuine fade. They can be combined.

A. Let GitHub credit the Hub again Recommended

Stop hiding the source on links from the Hub to our own GitHub repos. Keeps the security setting that matters, restores Hub attribution in GitHub reporting.

Effort: under 1 hourFixes: measurementVisible in about 14 days

B. Report one combined reach number Recommended

Track Hub sessions plus repo views plus unique cloners together. GitHub views alone now undercount by design, because the Hub is where people evaluate and download.

Effort: half a dayFixes: measurementVisible immediately

C. Measure Hub to GitHub click-through

Count every "View on GitHub" and "Download template" click on the Hub, so the handoff is measured directly instead of inferred.

Effort: 1 to 2 hoursFixes: measurementData from day one

D. Drop links after every session

Post the Hub guide link in the chat of each LevelUp, office hours and customer session. The Oct 19 LevelUp is a good test: if Teams-driven traffic does not lift within 10 days, the fade is real.

Effort: ongoing, minutes per sessionFixes: real fade

E. Keep a steady launch rhythm

New stars track launches. A visible release or major update every two to three weeks, announced in Teams, would keep momentum between big workshops.

Effort: team planningFixes: real fade

F. Do nothing and watch

Accept the GitHub number as structurally lower and track the Hub website instead. Low effort, but the GitHub number will keep looking like decline in reviews.

Effort: noneRisk: misread as lost traction
